## 2. 总体架构

### 2.1 设计原则

1. **分层解耦**：`cmd` → `internal` → `shortcuts`，业务逻辑不进 `cmd`
2. **基建先行**：配置、鉴权、HTTP、输出先于业务命令
3. **终局架构一次搭建**：目录按终局设计，后续只叠加能力与域
4. **体验统一**：三级命令、全局 flag、stdout/stderr 分离对标飞书

## 3. 三级命令体系

| 层级 | 飞书示例 | kuaimai-cli 示例 | 实现位置 |
|------|----------|------------------|----------|
| **1. 快捷 / 标准业务** | `calendar +agenda` | `item +list`、`item update-title` | `shortcuts/item/` |
| **2. 元数据 API** | `calendar events list` | `service item stock-list`、`service scm staff-query` | `cmd/servicecmd` + `meta_data.json` |
| **3. 原始兜底** | `api GET /open-apis/...` | `api POST /item/stock/queryList` | `cmd/api` |

`cmd/root.go` 注册顺序：`config` → `auth` → `api` → `schema` → `service` → `item` → `skill` → `completion` → `upgrade` → `doctor`。

### 3.1 两条路径不要混淆

```text
kuaimai-cli item +list --body '{"title":"关键字"}'
  → shortcuts/item/item.go
  → RunPOSTFormListMap → Execute（非 ExecuteWrite）
  → POST form /item/stock/queryList
  → 不读 meta_data 做路由（路径应与 meta 一致）

kuaimai-cli service item stock-list --body '{"pageNo":1,"pageSize":50}'
  → cmd/servicecmd + registry
  → meta `stock-list`：contentType=post_form、write=false、pageable=true
  → POST form /item/stock/queryList；`--page-all` 仅 pageable 时生效；查询不支持 `--dry-run`

kuaimai-cli service scm staff-query --body '{"pageNo":1,"pageSize":20}'
  → cmd/servicecmd + registry
  → meta `staff-query`：contentType=post_form、write=false、pageable=true
  → baseUrl 取自 scm service（https://scm.superboss.cc/），非 config api.url
  → POST form /staff/query；`--page-all` 仅 pageable 时生效
```

**重要区别**：

- `item +list` / `item list`：**不支持** `--dry-run`（走 `Execute`，非写管线）
- `service item stock-list`：查询接口 **不支持** `--dry-run`；**支持** `--page-all`（pageable=true）
- `service scm *`：**无 shortcuts**；baseUrl 固定 scm.superboss.cc，勿改 config `api.url`
- `item update-title`：**仅 shortcuts** 实现 get-detail → save 编排；`service item item-update-title` 为原子 save，需完整 `--body`

改接口时建议 **同时更新** `shortcuts/item/item.go` 与 `meta_data.json`（scm 仅 meta + Skill）。

Agent 如何从自然语言选择 shortcuts 或 service、何时查询 `schema`，见 [Agent 命令选型与 schema 流程](./Agent命令选型与schema流程.md)。

共 **2 个 service**（`item` **1095** + `scm` **195** 个 operation；`generated_at` 见文件）。

| operation | contentType | write | pageable | path | shortcut 别名 |
|-----------|-------------|-------|----------|------|---------------|
| stock-list | post_form | false | true | `/item/stock/queryList` | `item +list` / `item list` |
| stock-count | post_form | false | false | `/item/stock/queryCount` | `item count` |
| item-query-count | post_form | false | true | `/item/queryCount` | （无 shortcut；档案统计，见 `kuaimai-item-count-dimensions.md`） |

| item-save | post_json | true | false | `/item/saveItem` | `item save` |
| item-update-title | post_json | true | false | `/item/saveItem` | `item update-title`（编排仅在 shortcuts） |

## 4. 命令执行链路

### 4.1 Shortcut 通用流水线

`shortcuts/common/runner.go` 中 `Runner.Execute`：

1. `Factory.RequireAuth()` — 未登录则输出信封 + stderr 提示
2. `Factory.HTTPClient()` — 建客户端（自动附加 `accessToken` 头）
3. 业务 `RunFunc` — 发 HTTP 请求
4. `audit.Record()` — 写 `~/.kuaimai-cli/audit.log`
5. `Printer.Success/Fail` — 输出

三种执行模式：

| 模式 | 用途 | `--dry-run` | `--page-all` |
|------|------|-------------|--------------|
| `Execute` | 普通请求（如 `item +list`） | ❌ | form 列表在 `RunPOSTFormListMap` 内单独处理 |
| `ExecuteList` | GET 列表（如 `get-detail`） | ❌ | ✅ query `page`/`page_size` |
| `ExecuteWrite` | 写操作（save、count、service 层） | ✅ 预览 URL/body（脱敏） | ✅ form 翻页（`pageNo`/`pageSize`） |

### 4.2 示例：按标题查列表

```text
① cmd/root.go → PersistentPreRun → resolveOutputFormat（--output > cli.output > table）
② shortcuts/item/item.go → ParseBodyJSON → ApplyStockListDefaults
③ common.RunPOSTFormListMap("/item/stock/queryList", body)
④ internal/client → POST form {api.url}/item/stock/queryList
     Header: accessToken（auth login 写入密钥链后自动附加）
⑤ 快麦业务约定：响应 JSON 中 result==1 为成功（internal/client/bizresponse.go）
⑥ internal/output → 默认 table；--output json 时输出 {ok,data,error,hint}
     stderr: [debug]（--verbose）
```

`item list` 与 `item +list` **实现完全相同**，`+list` 仅为 Agent 友好的别名。

### 4.3 示例：修改商品标题

```text
item update-title --sys-item-id <id> --title "新标题" [--dry-run]
  ① GET /item/getItemDetail?sysItemId=…  → ExtractDetailItem
  ② PrepareSaveBody 合并标题（含 suiteBridgeList 等字段处理）
  ③ ExecuteWrite → POST JSON /item/saveItem
  dry-run 时第 ③ 步仅预览，第 ① 步仍会拉详情
```

等价手写路径：`item get-detail` → `jq` 改 `title` → `item save --body '…' --dry-run`。

### 4.4 配置与鉴权

```text
config init  → ~/.kuaimai-cli/config.yaml（api.url = erp1，cli.output = table）
auth login   → 系统密钥链（非 config 明文）；支持 --profile、--api-url
auth use     → 切换 auth.profile
请求头       → accessToken: <token>
```

| 能力 | 说明 |
|------|------|
| 唯一鉴权方式 | 用户提供的 `accessToken`（Agent **不可**代填，见 `auth.LoginHint`） |
| 多账号 | `auth login --profile <name>` · `auth list` · `auth use <name>` |
| per-profile API | `auth login --api-url` 或 config 中 `auth.profiles.<name>.api_url` |
| 探测 | `auth check` → POST form `/item/stock/queryCount`（最小探针，非调用 `item count` 子命令） |
| CI/测试回退 | 环境变量 `KUAIMAI_CLI_TOKEN_FILE` 指向 JSON 文件 `{profile: token}` |

## 5. dry-run 与 page-all（按代码）

全局 flag（`cmd/root.go` → `internal/core/context.go`）：

| flag | 说明 |
|------|------|
| `--dry-run` | 写操作预览 URL/body（脱敏），不发送 |
| `--page-all` | `pageable:true` 接口自动翻页 |
| `--page-limit N` | 与 `--page-all` 配合：最多拉取 N 条（0=不限条数） |
| `--page-confirm` | `prompt`（默认，交互 `[y/N]`）\| `yes`（自动继续）\| `no`（达阈值静默停止） |

分页实现：`internal/pagination` → `PostFormAllPages` / `RequestAllPages`。

**海量数据防护（CLI + Agent 对齐）**：

| 阈值 | 行为 |
|------|------|
| 已拉取 ≥ **500** 条 | 下一页前触发续查逻辑 |
| 接口 `total` > **1000** | 下一页前触发续查逻辑 |
| `--page-confirm prompt` | 交互终端询问；非交互环境停止并 stderr 提示 |
| 硬上限 | 最多 **1000 页**；分片合并每 **500** 条一块（`ChunkSize`） |

| 命令 | `--dry-run` | `--page-all` | 实现路径 |
|------|-------------|--------------|----------|
| `item +list` / `item list` | ❌ 仍会发请求 | ✅ | `RunPOSTFormListMap` → `Execute` |
| `item count` | ✅ 预览 form | ❌ | `RunPOSTFormMap` → `ExecuteWrite` |
| `item get-detail` | ❌ | ❌ | `RunGET` → `ExecuteList` |
| `item save` | ✅ 预览 JSON | ❌ | `RunPOST` → `ExecuteWrite` |
| `item update-title` | ✅ 预览 save（GET 详情仍执行） | ❌ | `Execute` + `ExecuteWrite` |
| `service item stock-list` | ❌ 查询 | ✅ pageable | `servicecmd` → `pagination` |
| `service item item-query-list-v2` | ❌ | ✅ pageable | 同上 |
| `service item stock-count` | ❌ | ❌ | `servicecmd` post_form |
| `service item item-detail` | ❌ | ❌ | `servicecmd` get_query + `--body` |
| `service item item-save` | ✅ | ❌ | `servicecmd` post_json |
| `service item item-update-title` | ✅ | ❌ | 原子 save（**无** get-detail 编排） |
| `api POST/PUT/DELETE` | ✅ | GET 可 `--page-all` | `cmd/api` |

联调建议：**写操作**对 `item save` / `item update-title` 使用 `--dry-run`；**列表探测**不要用 `item +list --dry-run`（无效）。

## 6. 输出与 Agent 约定

### 6.1 输出格式

| `--output` | 行为 |
|------------|------|
| `table`（**默认**） | 列表 → go-pretty 表格；map → KV 表；否则 fallback 完整 JSON 信封 |
| `json` | 完整 `{ok, data, error, hint}` |
| `csv` | 成功且 data 为 `[]map[string]any` 时裸 CSV；失败仍 JSON 信封 |
| `ndjson` | 成功且为列表时每行一条 JSON；空列表 fallback 信封 |

优先级：`--output` > `config cli.output` > `table`  
stderr：`--verbose` 日志与友好错误（**禁止**向 stdout 打日志、**无** Go 堆栈）

### 6.2 Skill 平台

| 项 | 说明 |
|----|------|
| 仓库内源 | `skills/kuaimai-shared/`、`skills/kuaimai-item/` v2.0.0（10 refs）、`skills/kuaimai-scm/` v1.0.0（7 refs） |
| 安装命令 | `skill install` · `skill install --if-stale` · `skill install kuaimai-scm`（覆盖写入各 Agent 目录） |
| 下载源 | GitHub Contents API 递归拉取 `skills/{name}/` 整目录；API 不可用时回退仅 `SKILL.md` |

## 8. 与飞书 lark-cli 对标

### 8.1 已对齐（架构层）

| 能力项 | 说明 |
|--------|------|
| 分层架构 | `cmd` → `internal` → `shortcuts` |
| 三级命令 | shortcuts（`+`）→ `service`（meta）→ `api`（兜底） |
| shortcuts | 手写高频 API，与 Controller 路径一致 |
| 元数据 | `registry` + `schema` + `service` |
| 鉴权存储 | 密钥链存 `accessToken` |
| 输出协议 | `{ok,data,error,hint}`；stderr 日志 |
| Agent 体验 | `--verbose` / `--dry-run` / `--page-all` / completion |
| Skill 平台 | `skills/` + `skill install`（GitHub 源） |
| 列表输出 | `csv` / `ndjson`；写操作 dry-run；脱敏与 `audit.log` |
| 分发模式 | `npx @kuaimai-cli/cli install`（结构对标 `@larksuite/cli`） |

### 8.2 主要差异（体量与体验）

| 维度 | 飞书 lark-cli | kuaimai-cli |
|------|---------------|-------------|
| 业务域 | 18 域、200+ 命令 | **2** meta 域（item + scm）、**6** item shortcuts |
| Agent Skills | **26** 个 | **3** 个（`kuaimai-shared`、`kuaimai-item`、`kuaimai-scm`）；风格已对齐飞书（references/、CRITICAL 路由） |
| 鉴权 | OAuth 交互式 + App 凭证 | `auth login <accessToken>`；无 OAuth |
| Agent 登录流 | `auth login --recommend`、`--no-wait` | 用户向管理员申请 token；见 [Agent 安装指南](./快麦 CLI 安装（Agent 专用）.md) |
| 身份切换 | `--as user` / `--as bot` | 多 profile（`auth use`），无 user/bot 概念 |
| 后端 | 开放平台 OAPI（2500+ API） | 私有 erp-items-core @ erp1 + erp-scm @ scm |
| 元数据规模 | 全量 OAPI | 内置 **1290** operation（item 1095 + scm 195）；**6** item shortcuts |
| 输出格式 | `--format json\|pretty\|table\|ndjson\|csv` | `--output table\|json\|csv\|ndjson`（**默认 table**，无 `pretty`） |
| 分页 | `--page-all` + `--page-limit` + `--page-delay` | `--page-all` + `--page-limit` + `--page-confirm`（**无** `--page-delay`） |
| schema 自省 | `schema <service.method>` | 全量 `schema` |
| 实时事件 | `event consume`（NDJSON 流） | 未实现 |
| 工作流 Skill | `lark-workflow-*` | 未实现 |
| 升级 | 生态成熟 | `upgrade` 默认一键升级；`skill install --if-stale`；CLI 版本变更后自动同步 Skills |
| 分发镜像 | npmmirror 回退 | GitHub → npmmirror `/-/binary/kuaimai-cli/`（须 cnpmcore 注册，见 [npmmirror 二进制镜像](./npmmirror-二进制镜像.md)） |

## 11. 总结

kuaimai-cli 在 **「CLI 架构 + Agent 协议 + meta 契约 + 分页防护」** 上已接近飞书 lark-cli 骨架；**业务覆盖面**的主要差距仍在 curated shortcuts 数量（飞书 18 域 / 26 Skill vs 当前 2 meta 域 / 6 item shortcuts / 3 Skill）。

1. **框架已定稿**：meta v1.7.0（1290 op）+ Skill + CLI 分页/dry-run/Schema 全链路闭环
2. **P1 主战场**：按 ERP 场景扩 item shortcuts 与 Skill references（meta 登记即可用 `service`）
3. **P2～P3**：pretty、单 op schema、`--page-delay`
4. **策略不变**：少域、深 shortcuts（item）、强 Skill（item + scm）、真实场景闭环

理解 API 映射时：

- **`item *`** → `shortcuts/item`（含编排型 `update-title`）
- **`service item *`** → `meta_data.json` item 域（1095 原子 API，无编排）
- **`service scm *`** → `meta_data.json` scm 域（195 原子 API，自动 scm baseUrl）
- **`api`** → 终端传入 path
