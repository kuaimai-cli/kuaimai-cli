## 1. 定位与完成度

| 维度 | 现状 |
|------|------|
| **产品定位** | 快麦 ERP 商品 + 供应链 CLI，架构与交互对标飞书 lark-cli |
| **接口真相源** | 远端 [registry.json](http://open-cli.kuaimai.com/registry/registry.json)（`schemaVersion: 2.0`），由 `kuaimaierp-cli-auto` 生成发布 |
| **CLI 消费** | 自动同步到 `~/.kuaimai-cli/registry/registry.json` → `capabilities` / `schema` / `web call` |
| **后端对接** | 经 `open-cli.kuaimai.com/api/forward` 转发至 erp1 / scm（registry `baseUrl`） |
| **shortcuts** | item 域 6 个子命令（手写编排，**不**来自 registry） |
| **Skill** | `kuaimai-shared` v1.1 + `kuaimai-erp-item` v3 + `kuaimai-scm-item` v2（意图路由 + 工作流，**不**维护接口表） |
| **对标完成度** | 架构 / Agent 协议 ~95%；业务覆盖面 ~8%（飞书 18 域 / 26 Skill vs 当前 3 Skill + 6 shortcuts） |
| **过渡期** | 远端 registry 逐步收录 item/scm 全量 apiId；此前文档中的 meta v1.7.0（1095+195 op）为历史生成物，**不再内嵌 CLI 二进制** |

## 2. 总体架构

### 2.1 设计原则

1. **registry 与 CLI 解耦**：接口 JSON 由 `kuaimaierp-cli-auto` 生成，CLI 只消费
2. **分层解耦**：`cmd` → `internal` → `shortcuts`
3. **体验统一**：三级命令、全局 flag、stdout/stderr 分离对标飞书
4. **Skill 管工作流，registry 管接口**：对标飞书 lark-calendar + 内嵌 OpenAPI

```text

│  用户 / Agent（AGENTS.md + Skill：shared / item / scm）       │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│  cmd/  config · auth · api · capabilities · schema · web   │
│        registry · item(shortcuts) · skill · doctor · upgrade │
└───────────────────────────────┬─────────────────────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│ shortcuts/erp-item│     │ cmd/webcmd    │     │ cmd/api       │

└───────┬───────┘     └───────┬───────┘     └───────┬───────┘
```

### 2.3 目录职责

| 目录 | 职责 |
|------|------|
| `cmd/webcmd` | `web call <apiId>` |
| `cmd/capabilitiescmd` | 列出 registry apiId |
| `cmd/schemacmd` | 全量或单 apiId 自省 |
| `cmd/registrycmd` | `registry sync` / `watch` |
| `cmd/bootstrap.go` | 命令前自动 SyncIfNeeded |
| `internal/registry` | v2 解析、`Sync`/`SyncIfNeeded`、本地缓存 |
| `internal/apicall` | registry 驱动 HTTP 执行 |
| `shortcuts/erp-item` | 6 个 curated 商品命令 |
| `skills/` | Agent 工作流源（随 npm 发布） |

**本地落盘**（`~/.kuaimai-cli/`）：

| 路径 | 用途 |
|------|------|
| `config.yaml` | api.url、registry.source、cli.output |
| `registry/registry.json` | 远端 registry 缓存 |
| 系统密钥链 | accessToken（多 profile） |

## 3. 三级命令体系

| 层级 | 飞书 | kuaimai-cli | 实现 |
|------|------|-------------|------|
| **1. Shortcuts** | `calendar +agenda` | `erp-item +list`、`erp-item update-title` | `shortcuts/erp-item/` |
| **2. web call** | `calendar events instance_view` | `web call api.luotao.test.get` | `cmd/webcmd` + registry |
| **3. api** | `api GET /open-apis/...` | `api POST /item/stock/queryList` | `cmd/api` |

**已移除**：`service` 命令（与 `web call` 重复，终态统一 apiId 调用）。

`cmd/root.go` 注册：`config` → `auth` → `api` → `schema` → `capabilities` → `web` → `registry` → `item` → `skill` → `completion` → `upgrade` → `doctor`。

registry 自动同步发生在 Cobra 解析后的 `PersistentPreRunE`，只对 registry-backed 命令执行；`config/auth/doctor/skill/registry/upgrade/completion/help/version` 跳过同步，避免安装、登录、自检等基础命令被远端 registry 可用性阻断。

### 3.1 两条路径不要混淆

```text
erp-item +list
  → shortcuts/erp-item（不读 registry 路由；路径硬编码 /item/stock/queryList）
  → 内置 ARCHIVE_V2 默认 body

web call item.stock-list
  → registry 缓存 → apicall.Execute
  → 同 path，无 shortcut 默认 body；参数以 schema 为准

web call scm.staff-query
  → registry baseUrl → https://scm.superboss.cc/
```

**编排差异**：`erp-item update-title` 仅存在于 shortcuts（get-detail → save）；`web call item.item-update-title` 为原子 save。

### 3.2 Registry v2 协议（当前）

```json
{
  "schemaVersion": "2.0",
  "version": "2026.06.11.3",
  "domains": { "商品": { "apiIds": ["api.luotao.test.get"] } },
  "apis": {
    "api.luotao.test.get": {
      "method": "GET",
      "path": "/api/luotao/test/get",
      "contentType": "get_query",
      "requestSchema": { ... }
    }
  }
}
```

**Agent 发现流程**（不写死在 Skill）：

```bash
kuaimai-cli capabilities --output json
kuaimai-cli schema <apiId> --output json
kuaimai-cli web call <apiId> --params|--data|--body '...'
```

item/scm 历史 apiId 命名约定：`item.stock-list`、`scm.staff-query`（待 api-onboard 全量发布至远端）。

### 3.3 命令树

```text
kuaimai-cli
├── config / auth / api
├── capabilities
├── schema [apiId]
├── web call <apiId>
├── registry sync | watch
├── item  (+list | list | count | get-detail | save | update-title)
├── skill / completion / upgrade / doctor
```

## 4. 命令执行链路

### 4.1 web call

```text
web call <apiId>
  → registry.Load()（本地缓存）
  → FindByAPIID → apicall.Execute
  → 按 contentType 发 GET query / POST form / POST JSON
  → Runner（auth、dry-run、page-all、output 信封）
```

### 4.2 Shortcut 流水线

`shortcuts/common/runner.go`：`Execute` / `ExecuteList` / `ExecuteWrite`  
写操作支持 `--dry-run`；`erp-item +list` 查询走 `Execute`，**不支持** dry-run。

### 4.3 鉴权

`auth login` → 密钥链 `accessToken` → 请求头自动附加。多 profile：`auth use`。

## 5. dry-run 与 page-all

| 命令 | `--dry-run` | `--page-all` |
|------|-------------|--------------|
| `erp-item +list` | ❌ | ✅ |
| `erp-item save` / `update-title` | ✅ | ❌ |
| `web call`（write:true） | ✅ | 视 pageable |
| `web call`（write:false） | ❌ | 视 pageable |

阈值：≥500 条或 total>1000 触发 `--page-confirm`；硬上限 1000 页。

## 6. Skill 平台（对标飞书 lark-*）

### 6.1 分工

| 组件 | 职责 | 对标飞书 |
|------|------|----------|
| **kuaimai-shared** | auth、输出、registry 发现流程 | lark-shared |
| **kuaimai-erp-item** | 商品意图路由、shortcuts、references | lark-calendar |
| **kuaimai-scm-item** | 供应链意图路由、references | lark-scm 类域 Skill |
| **registry** | 接口清单 + schema | 飞书内嵌 OpenAPI |

**Skill 不维护全量接口表**；参数以 `schema <apiId>` 为准。

### 6.2 安装

```bash
kuaimai-cli skill install              # kuaimai-shared + item + scm
node npm/scripts/sync-skills.js        # 发版前：skills/ → npm/skills/
```

安装目录：`~/.agents/skills`、`~/.cursor/skills`、`~/.codex/skills`、`~/.claude/skills`、`~/.windsurf/skills`。安装器和 Go 侧 `skill install` 都要求 5 个目录中的默认 Skill 与 `references/` 齐全；`doctor --output json` 的 `skill_roots` 字段可定位具体缺失目录。升级后重开 Agent 会话。

## 7. 与飞书 lark-cli 对标

### 7.1 已对齐

| 能力 | 说明 |
|------|------|
| 三级命令 | shortcuts → web call → api |
| Registry | 飞书内嵌 vs 快麦远端 JSON + 自动同步 |
| schema 自省 | `schema [apiId]` |
| Skill 分工 | shared + 域 Skill + references |
| 输出 / 分页 / dry-run | 信封协议、page-all 防护 |
| 分发 | `npx @kuaimai-cli/cli install` |

### 7.2 主要差异

| 维度 | 飞书 | 快麦 |
|------|------|------|
| 元数据调用 | 18 个域顶层命令 | 统一 `web call <apiId>` |
| Registry 源 | CLI 内嵌 | 远端 open-cli + 本地缓存 |
| Skill 数量 | 26 | 3 |
| 鉴权 | OAuth | accessToken |
| 远端 registry 规模 | 2500+ API | 逐步发布（当前以测试 api 为主） |

### 7.3 对照速查

```text
飞书                              快麦
lark-shared                       kuaimai-shared（含 registry 流程）
lark-calendar                     kuaimai-erp-item（shortcuts + 工作流）
calendar events instance_view     web call <apiId>
lark-cli schema calendar.events.x kuaimai-cli schema <apiId>
npx skills add larksuite/cli      kuaimai-cli skill install
```

## 9. 联调提示

1. `config init` → `api.url` = erp1
2. `registry sync` → `capabilities` 确认 apiId 已发布
3. 商品高频：`erp-item +list` → `erp-item update-title`

## 10. 总结

kuaimai-cli 已完成 **registry 中心化**改造：

1. **接口**：远端 registry.json 为唯一真相源，CLI 同步消费
2. **调用**：`capabilities` → `schema` → `web call`（对标飞书 schema + 域命令）
3. **shortcuts**：item 6 命令仍手写，Skill 管意图与工作流
4. **下一步**：api-onboard 扩远端 registry；Skill 随 domain 演进，不再膨胀接口表
